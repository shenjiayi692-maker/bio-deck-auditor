## 1. 核实对象

优先核实材料主动给出的可证伪锚点：DOI、论文标题、NCT/ChiCTR 号、注册证/受理号、专利号、客户/合作方和团队履历。

商业收入、回款和合同条款通常没有完整公开数据库，仍需原始合同、发票、流水或独立访谈。

## 2. 状态机

```text
deck_unverified
  ├─ 搜索命中 → candidate
  │    ├─ 关键字段一致 → verified
  │    └─ 关键字段不一致 → contradicted
  └─ 查询失败/无结果 → unverifiable
```

无结果不自动进入 `contradicted`。记录查询范围、日期、关键词、数据库限制和下一步。

## 3. 匹配规则

只有逐项匹配才标 `[已核实]`：

- **论文**：DOI 优先；否则标题、作者、年份、期刊共同匹配。引用数标数据库和查询日期。
- **试验**：登记号优先；匹配申办方、阶段、样本量、主要终点、状态和时间。
- **专利**：匹配公开号、类型、法律状态、申请人、同族和权利要求范围。
- **注册**：匹配产品名、注册人、类别、适用范围、状态和有效期。
- **客户/合作**：公开新闻只能证明公开陈述；合同、金额和回款仍需原始证据。

“记录存在”不证明证据充分。例如 30 人观察性研究不能支持“万人级前瞻临床验证”。

## 4. 脚本

完整 CLI 见 `references/common/script-usage.md`。

| 对象 | 脚本 | 输出能力 |
|---|---|---|
| 论文/引用 | `scripts/verify_refs.py` | DOI/标题候选、引用口径、作者和单位线索 |
| 国际试验 | `scripts/verify_trials.py --nct/--ctgov` | NCT 存在性或关键词候选；仍需字段比较 |
| ChiCTR | `scripts/verify_trials.py --chictr-*` | 半自动候选/存在性，可能受验证码影响 |
| 专利 | `scripts/verify_patents.py` | 检索入口和人工清单，不作最终法律状态结论 |
| NMPA 线索 | `scripts/cn_reg_sources/` | 生产许可/UDI 等有限线索，不是完整注册证或受理核查器 |

## 5. 降级与记录

优先级：官方登记库/批文 → 权威结构化数据库 → 目标机构公开页面 → 搜索引擎候选 → 原始文件索取。

报告中记录：

| 宣称 ID | 来源 | 查询参数 | 日期 | 状态 | 匹配字段 | 未匹配字段 | 限制 |
|---|---|---|---|---|---|---|---|

不得把脚本输出原样贴进报告；把它转换成宣称级结论，并保留来源链接和查询日期。
