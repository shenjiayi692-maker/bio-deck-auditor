## 1. 规则类型

先判断一条审计规则属于哪类：

| 类型 | 定义 | 用法 |
|---|---|---|
| 硬规则 | 法规原文、正式标准、合同条款、确定性算术 | 满足前提后可直接判断 |
| 强先验 | 有透明样本和稳定行业数据支持 | 作为起点，允许个案证据推翻 |
| 启发式 | 常见模式或经验阈值 | 只触发追问，不直接定罪 |
| 案例经验 | 单个项目、访谈或未公开经验 | 仅作情景参考 |

毛利率、客户集中度、销售周期、注册周期和“通常需要”默认属于启发式或强先验，除非提供适用口径和来源。

## 2. 证据等级

| 等级 | 示例 |
|---|---|
| A | 监管数据库、正式批文、审计财务、签署合同原文、预注册高质量临床结果 |
| B | 同行评议论文、权威指南、可复核第三方数据库、银行流水或发票 |
| C | 公司提供的原始数据、未审计财务、客户访谈、未发表研究 |
| D | Deck 陈述、新闻稿、Logo 墙、管理层口述 |
| E | 推测、类比、无法追溯的二手统计 |

证据等级不自动决定结论。检查来源是否独立、是否匹配同一产品/主体/期间、是否完整披露不利结果。

## 3. 严重度与置信度

分开记录：

- **严重度**：若问题属实，对投资逻辑的影响有多大。
- **置信度**：现有证据多大程度支持问题确实存在。

例如“核心临床试验可能未注册”可以是 `影响：严重；置信度：低`，直到完成多个登记库检索或取得注册号。

## 4. 更新规则

每条结论独立更新，不设置“最多软化几条”等配额。

1. 写出原结论和支持证据。
2. 检查新证据是否匹配同一实体、时间和宣称。
3. 检查来源独立性和可复核性。
4. 更新事实状态、严重度或置信度。
5. 记录“因何证据、从何状态改为何状态”。

合理替代解释存在时，列入 `counterevidence`，并说明如何区分。不要因为报告需要“平衡”而虚构优点，也不要因为采取红队视角而忽略真实反证。

## 5. 常见误判

- 数字对不上可能来自期间、币种、累计/当期、含税或四舍五入；先核口径。
- 低毛利可能来自云推理、数据采购、渠道或客户成功成本，不自动等于硬件公司。
- 公司成立前论文可证明团队能力，也可能通过许可/转让成为资产；必须查成果转化文件。
- 搜到同名论文、试验或公司不等于匹配了 deck 中的实体。
- 未检索到记录不等于记录不存在；说明检索范围和限制。
- 缺少分层数据首先是证据缺口；只有在法规、标准或材料声称明确要求时才直接升级红旗。
