# 法律实体、产品组合与权利边界

融资材料常把品牌、集团、子公司、实验室和合作医院合并叙述。分析前先画边界，否则注册证、收入、专利和团队可能被归给错误主体。

## 实体图

| 节点 | 核查内容 |
|---|---|
| 融资主体 | 本轮投资进入哪家法律实体 |
| 品牌/网站主体 | 对外品牌和合同主体是否一致 |
| 母子公司/关联方 | 持股、控制、共同创始人及关联交易 |
| 注册/许可持有人 | 每张证属于谁，能否授权融资主体销售 |
| 生产主体 | 自产、委托生产、OEM；质量责任与毛利归属 |
| IP/数据权利人 | 专利、代码、模型、商标、临床数据和许可范围 |
| 收入确认主体 | deck 营收属于单体、集团合并还是关联公司 |
| 员工与顾问 | 劳动关系、兼职、服务协议和成本承担主体 |

名称相似、品牌相同或创始人相同不证明资产可由融资主体支配。要求提供股权结构、关联方清单、许可/经销/委托生产协议和合并口径说明。

## 产品—证照矩阵

逐 SKU/版本建立：

`法律实体 → 产品名/型号 → 软件版本 → 预期用途 → 注册证/许可号 → 适用范围 → 生产企业 → 上市地区 → 收入`

- 一张证只覆盖批文中的产品、型号、版本和用途。
- “软硬耗一体化”通常包含多个注册单元、生产主体与毛利结构，分别核实。
- 后续新增模块、跨科室适应症或硬件组合不能自动继承原软件证。
- 用关联公司的证销售时，核查授权、质量协议、收入分成和控制权变化后的持续性。

## 时间边界

为每个事件记录 `announced_at`、`effective_at` 和 `verified_at`。deck 日期以后或审计时点以后的注册、融资、奖项、收入只能标为计划或预测；接近审计时点的事件仍需查正式生效记录。
