# 评测协议

用盲测案例同时监测漏报和误报。不要只用“有问题的 deck”评测，否则会训练出确认偏误。

## 案例分层

至少覆盖：真实一致宣称、算术差异、图表标签与缓存值不一致、口径差异、品牌与法律实体错配、证照持有人与融资主体不同、历史收入早于实体成立、试用/装机/活跃使用混算、关键词误命中、登记号仅证明存在、公司成立前论文但已合法转让、医疗服务价格被误当企业收入、跨业务依赖、上市后质量信号、开源模型到商业产品的外推、信息不足、明确外部矛盾，以及强正面证据。

每个案例保存输入、最低必需观察、禁止结论、期望证据状态、严重度范围和可消除不确定性的下一步动作。`scripts/tests/fixtures/eval_cases.json` 提供最小行为夹具。

## 指标

- 宣称提取召回率：关键数字、限定词、脚注与图表宣称是否入台账。
- 多媒体覆盖率：备注、图表缓存值、二维码、视频和隐藏页是否被发现或标记人工复核。
- 实体匹配精度：候选记录是否被错误升级为已核实。
- 权利归属精度：证照、IP、收入和融资是否归到正确法律实体及产品版本。
- 数字核查精度：能否区分算术错误与口径未知。
- 证据校准：置信度是否随来源质量变化；查不到是否被误判不存在。
- 严重度校准：严重度与置信度是否分离。
- 反证响应：新增可靠证据后是否更新结论，不受既往红旗数量影响。
- 估值纪律：数据不足时是否退回情景或隐含假设，避免单点伪精确。

## 回归流程

1. 对固定夹具生成报告并隐藏期望答案。
2. 由两名评审独立打分，分歧先统一 rubric 再裁决。
3. 分别统计误报、漏报、错误升级、错误归零和无来源数字。
4. 每次修改方法论或脚本后重跑；新增真实失败案例时先去标识化。
5. 不把评测样本中的公司结论写回通用规则，只修复可泛化的行为。
