## 1. ★ 第一问:这个SaaS是不是器械? ★

**这是本子领域最有杠杆的判断,因为答案改变一切:估值方法、时间线、成本、壁垒。**

判定依据是**预期用途**,不是技术形态:

| SaaS 做什么 | 大概率定性 |
|---|---|
| 医院管理、排班、库存、计费、HR | ✅ 普通SaaS,不受器械监管 |
| 数据展示、报表、患者沟通 | ✅ 普通SaaS |
| 健康科普、生活方式管理(不做疾病声称) | ✅ 通常不受器械监管 |
| **辅助诊断 / 疾病风险预测 / 影像分析** | 🔴 **医疗器械(SaMD)** |
| **临床决策支持(CDS)** | ⚠️ **边界地带——这是最常见的越界点** |
| **给出治疗建议 / 用药建议** | 🔴 大概率是器械 |
| **分诊/预警(如脓毒症预警)** | 🔴 大概率是器械 |

### "临床决策支持"是SaaS变器械的头号触发点

**审计动作:如果一个SaaS开始给临床建议,追问三件事:**
1. **它给的是"信息"还是"结论"?**(展示数据 vs 给出诊断/建议)
2. **医生能不能独立复核它的依据?**(如果医生能看到并独立判断依据 → 更可能豁免;如果是黑箱输出结论 → 更可能是器械)
3. **它的输出会不会直接驱动临床行动?**(会 → 器械)

**⚠️ 关键红旗:一个自称"我们只是效率工具,不受监管"的SaaS,如果它的deck里同时在讲"AI辅助诊断""提升诊断准确率""疾病早筛"——它在两套说辞之间套利。** 这两套不能同时为真。

**NMPA 历史先验（见 `references/common/empirical-nmpa-ai.md`）**：旧版第三方样本中的独立 AI 医用软件高度集中于三类，但口径不可复现，不能直接给具体产品定类。应按预期用途、输出、临床后果和正式分类界定逐产品判断。

**判定后果:**
- **是器械** → 立刻切换到 `medical-device` 子领域的框架:走rNPV,加上注册周期、临床成本、物价编码。**估值方法完全不同**
- **不是器械** → 用普通SaaS估值,但要过下面三关(账期、集成、试点炼狱)

## 2. 关键路径(非监管里程碑)

若确认不是器械,本子领域没有监管里程碑链,取而代之的是:

```
PMF → 首批医院付费 → 可复制交付 → 规模化 → 续费/留存
                        ↑
              重点核查这里（若每家医院都需大量定制，项目制成分上升）
```

**核心检验:可复制性。**
- 第二家医院的交付成本,比第一家低多少?
- 如果每家医院都要大量定制开发 → 拆分标准软件、实施和定制收入，按各自复用性与毛利估值（见 `references/common/cross-domain.md`）

## 3. ★ 回款账期:公立医院的现金流黑洞 ★

**公立医院的回款周期通常 6个月以上**,实践中1年+并不罕见。

**为什么这对SaaS是致命的:**
- SaaS的估值逻辑建立在"经常性收入"上,但**收不到的钱不是收入**
- 账面ARR增长 + DSO持续拉长 = **现金流在恶化,而报表看不出来**
- 早期公司死于现金流断裂,而不是收入不够

**必查(优先级高于ARR):**
1. **DSO(应收账款周转天数)** — 索取这个数字。**不给就是🟠红旗**
2. **应收账款账龄结构** — 超过1年的有多少?
3. **坏账计提** — 有没有计提?比例合理吗?
4. **现金收入 vs 账面收入** — 两者的差距
5. **融资有多少用于填补账期和营运资金?** — 若占比较高，材料应把“增长资本”和营运资金需求分开披露

**⚠️ 与 medical-device 相通**:任何卖给公立医院的业务(设备或软件)都有这个问题。**交叉公司要合并看总的应收压力。**

## 4. ★ EHR/HIS 集成成本:吃掉毛利的隐形怪兽 ★

**这是医疗SaaS最被低估的成本项,也是"看起来是SaaS,实际是外包"的根源。**

中国医院的HIS/EMR系统高度碎片化、大量定制、厂商林立。一个SaaS要真正跑起来,通常需要:
- 与该院的HIS/EMR/LIS/PACS 做数据对接
- 每家医院的接口、数据结构、字段定义都不一样
- 医院IT科室配合意愿低、排期长
- 原HIS厂商可能不配合(**他们视你为竞争者**)

**后果:每家医院的实施成本极高,而且不随规模下降。**

**必查:**
1. **单个客户的实施成本(人天)是多少?** 第10个客户比第1个便宜多少?
2. **实施成本占合同金额的比例?** 结合合同期限、续费、标准化程度和边际交付成本判断；不以单一阈值改判业务类型
3. **毛利率与成本归类**:拆出云推理、数据、实施、渠道和客户成功。低毛利提示复用性问题，但不能单凭阈值判定为外包
4. **有没有标准化的对接方案?** 还是每家从头做?
5. **HIS厂商的态度**:是合作方还是拦路虎?

**判定**:一家"医疗SaaS"公司,如果实施成本高、毛利率低、每家都要定制 → **按项目制/外包公司估值,不能给SaaS倍数。** 这是本子领域最常见的估值错配。

## 5. Pilot Purgatory(试点炼狱)

医疗行业最著名的死法:**POC签了一堆,零转化。**

- 医院企业级销售周期通常 **12-18个月**
- 医院很乐意做"免费/低价试点"(有科研价值、有政绩),但**转化为付费规模采购极难**
- 预算从哪出?设备科?信息化?**科研经费(=一次性,不可持续)?**

**必查:**
1. **POC数量 vs 转化为付费的数量。转化率是多少?**
2. **付费的那几家,付了多少?是不是科研经费?**
3. **有没有第二年续费或扩容?** 续费是强证据之一，同时检查合同期限、使用深度、回款和净收入留存
4. **决策链**:谁签字?科室主任?院长?招标?——链条越长,周期越长

**"我们进了N家三甲医院"这句话必须被拆开:是科研合作还是采购?付了多少钱?可复制吗?** 标 `[据deck·未核实]`。

## 6. 估值方法选择

| 情形 | 方法 |
|---|---|
| **被判定为器械** | **切到 medical-device 框架,用 rNPV** |
| 真SaaS(高毛利、可复制、有续费) | SaaS倍数(ARR × 倍数),但**倍数需按医疗行业的长销售周期和账期打折** |
| 伪SaaS(低毛利、每家定制) | **项目制/人头制估值(最低倍数)** |
| 早期(无续费数据) | 期权法 / 谨慎的可比交易 |

**⚠️ 医疗SaaS 不能直接套通用SaaS的倍数。** 三个折价因素:
1. 销售周期长(12-18月)→ 增长慢
2. 账期长(6月+)→ 现金流差
3. 实施成本高 → 毛利低于通用SaaS

## 7. 与器械业务交叉时(常见组合)

**器械+SaaS 是极常见的组合。先按 `references/common/cross-domain.md` 定结构:**

| 情形 | 结构 | 处理 |
|---|---|---|
| SaaS的数据/客户全部来自自家设备 | **依赖型(乘法)** | SaaS期望值 × P(设备成功)。**不能相加** |
| SaaS有独立的第三方客户(不依赖自家设备) | **组合型(加法)** | 分部估值,各用各的模型和折现率 |
| 公司用SaaS的高倍数,去套硬件为主的业务实质 | **伪装型** | 毛利测谎 → 按实质给倍数 |

**⚠️ 监管交叉的关键**:如果SaaS模块被认定为器械的一部分(软硬件组合注册),**整个产品都要走器械路径**,SaaS部分不能单独享受"无监管"的快速变现。**最严的那条路径决定整体。**

**占比怎么定**:见 `references/common/cross-domain.md` 的"三口径交叉验证"(收入占比 / **毛利占比** / 资源投入占比)。**毛利占比比收入占比更接近真实价值贡献。**
