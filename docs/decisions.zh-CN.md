# 设计决策

[English](decisions.md) · **中文**

README 说明了这套方法**做什么**，[三份 deck 的盲测复盘](../outputs/three-deck-blind-audit-2026-07-17.md) 记录了它在真实材料上**跑出了什么**。这份文档说明**为什么是这些边界而不是别的**：每条决策对应一个被否掉的替代方案，以及这个选择付出的代价。六条决策比其余的更重要。

## 第一步是建台账，不是下判断

自然的做法是读完整份 deck 形成整体印象，再回头找证据支持它。这也是人类分析师实际的工作方式，快得多，而且对写得好的材料往往足够。

它被否掉，是因为 deck 的问题很少是某句话说错了。问题是**跨页口径对不上**，而整体叙事恰好是最能把跨页矛盾抹平的东西——一旦先形成判断，后面找证据就变成找支持性证据。柳叶刀那份材料是这件事的实证：收入预测图的页面可见标签是 2025–2030 年 3,000 / 8,000 / 16,000 / 25,000 / 38,000 / 50,000 万元，PPT 图表的底层缓存值却是 6,000 / 15,000 / 30,000 / 60,000 / 80,000 / 100,000。两套数字从不出现在同一页，读完写观点的流程不可能发现它。所以流程的第一步是把每条宣称拆出来，带上页码、原文、类型、法律实体、产品/版本、时间属性、辖区、证据形态。

**代价：** 八个字段乘以一份 deck 的全部宣称，前期工作量远高于直接写观点，而且大多数宣称上大多数字段是空的。这套方法对一份干净的早期 deck 是过度工程。

## 事实分五档，不是三档

已核实 / 未核实 / 与材料矛盾，三档就够用，也最好向人解释。

它被否掉，是因为三档把两组不同的事各压成了一件。一组在"未核实"这一侧：关键词检索命中、但实体、申办方、状态、时间没有逐项对上的宣称，和根本还没去查的宣称，在三档里落进同一格；前者差一步就能升级，后者连方向都还没有。另一组更要紧——三档没有位置安放"我找过、找不到、以下是我找过的地方"。没有这一格，**查不到就会被当成不存在**，而这是初筛里代价最高的一类错误。所以有 `[候选记录·尚未匹配]` 和 `[无法核实·已说明尝试]` 这两档，升级到 `[已核实·来源]` 必须逐项比对。

**代价：** 每条宣称多一次判断，报告更长，读者要先认得五个标记才能读第一页。

## 红旗严重度和证据置信度是两根轴

一个 0–100 的风险总分，排序、比较、跨项目汇总都方便，也是基金团队真正想要的东西。

合并之后，"影响很大但我不确定"和"影响不大但我很确定"会得到同一个分数，而这两种情况要的下一步动作正好相反：前者是去查，后者是定价。🔴🟠🟡 说的是潜在影响，高/中/低说的是判断者有多确定，两者不通约。同一条规则还有一个推论：缺信息默认落在待核实项，不自动升级为红旗，否则材料写得简略的公司会仅仅因为写得简略而被打成高风险。

**代价：** 给不出"这个项目多少分"。报告必须被读，不能被扫，这和基金内部筛项目的实际节奏是冲突的。

## 商业证据分层，且不许合并计数

直接采用 deck 自己的口径——客户数、覆盖医院数——最省事，也最容易横向比较。

它被否掉，是因为"合作 30 家医院"和"回款 30 家医院"差着五个台阶，而在一张汇总表里两者长得完全一样。柳叶刀那份同时出现"30 台出货/装机"和"50+ 医院试用/装机"：两个数字既不矛盾也不可加，因为口径不同，而 deck 没有义务告诉你这一点。所以统一拆成 线索 → 试点 → 付费合同 → 交付 → 验收 → 回款 → 活跃使用 → 续约/复购 → 扩单，医疗设备再加逐台 utilization、停机率、售后成本和耗材附着率。

**代价：** 多数 deck 给不出分层所需的数据，于是报告里大片格子是空的，读起来像在挑刺。这些数据只能向企业索取，会实质性拉长初筛流程。

## 一张注册证只核实矩阵里的那一格

公司拿得出 FDA 或 NMPA 的证，监管这一层就算过了——这是绝大多数初筛的实际做法。

它被否掉，是因为证证明的东西比它看起来窄得多。柳叶刀的 FDA 510(k) K220774 确实可核实：产品 RobPath Total Hip Application，申请人 Hangzhou Lancet Robotics，决定日期 2022-12-09。但 deck 的融资主体是深圳柳叶刀。这张证是真的，它证明的是特定法人、特定产品、特定预期用途，不能自动证明深圳主体拥有全部资产，更不能证明整个跨科室平台都已注册。同一份材料里标题称 11 张三类证，可见清单只展开约 10 项。所以多产品公司要先建"法律实体—产品 SKU—版本—注册证—适用范围—生产主体—收入"矩阵，一张证不向别的适应症、别的模块、关联公司外推。

**代价：** 集团项目的第 0 步变成建实体图，而这件事在只拿到一份 deck 的情况下往往做不完，结论就只能停在"需澄清"而不是给出评级。

## 估值随数据量降级输出，而不是硬给一个倍数

套可比公司倍数、给出"当前估值高估 N 倍"，是投资人最想从初筛里得到的一句话。

它被否掉，是因为倍数的分母是收入预测，而收入预测恰好是 deck 里最不可靠的数。柳叶刀按 15 亿元投前估值计算，用页面可见标签还是用图表底层缓存值，收入倍数差一倍以上——在分母本身有两个版本的时候给出一个倍数，是把精度伪装在一个不成立的输入上。所以数据够了才做 rNPV；概率稀薄就给情景区间；再不够就只反推"当前估值隐含哪些里程碑必须达成"。

**代价：** 最想要的那句话经常给不出来，而且给不出来的次数会随着材料质量下降而上升——也就是越需要判断的时候越沉默。

## 盲测复盘之后改了什么

上面六条里有四条不是设计出来的，是 2026-07-17 那次三份 deck 盲测跑出来的。复盘列了九项流程缺口，其中审计时点与时间属性、法律实体—资产—收入边界、产品—版本—证书矩阵、商业证据阶梯四项被从"某个领域模板里的补充项"提升为所有 deck 的通用流程。图表底层缓存取证也是在那次之后才从边缘功能变成核心尽调能力——柳叶刀的收入图证明了它不是可选项。

复盘同时确立了一条停止规则：当融资主体无法证明拥有关键证照/IP/收入、核心图表出现两个版本、注册用途与商业宣称不一致、或估值输入缺失到无法形成可信区间时，系统从"评分"转为"需澄清/暂缓"，而不是带着标注继续打分。

这套东西能自动到哪一步，是被数据源决定的，不是被架构决定的。ClinicalTrials.gov 有公开 API，所以试验核验是确定性的；ChiCTR 没有 API，只能爬，可能卡验证码，失败就退回人工并给出检索 URL。README 的自动化边界表把这条线画在明处，是因为一个声称全自动、实际在某些辖区悄悄降级的工具，比一个说清楚自己边界的工具更危险。

复盘本身的结论也留在这里：这套方法目前更像一个质量不错的 analyst copilot 原型，还不是能稳定交付给基金团队的产品。
